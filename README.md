## The problem

An AI agent rarely acts through one permission.

Its effective authority may be assembled from:

- declared tools
- MCP servers
- APIs
- workspace configuration
- environment-variable references
- external actions
- inherited credentials
- combinations of otherwise ordinary capabilities

The useful question is not simply:

> What is this agent called?

It is:

> What can this agent actually reach, and what changed since the last review?

---

## 8 checks before you let an agent act

- [ ] Inventory the agent manifest and configuration.
- [ ] List declared tools and actions.
- [ ] Identify connected MCP servers.
- [ ] Review credential-shaped environment-variable names.
- [ ] Map reachable APIs and external systems.
- [ ] Look for capability combinations that create dangerous action chains.
- [ ] Establish an authority/change baseline.
- [ ] Re-check operator or public evidence where available.
